# 内置 VSCode

[返回 README](../README.md) · [功能总览](../README.md#功能)

一个只用页面实现的轻量编辑器：读的是 DSH 的工作区，编辑、搜索、Git、PowerBuilder 设计器都在同一扇窗口里。没有终端、扩展市场和调试器——界面上只放真正能用的东西。

## 窗口与工作区

开始菜单「应用」分组里的第一个内置应用。安装后桌面出现图标、任务栏出现窗口按钮；第一次打开时默认落在**当前 DSH 主视图会话的工作目录**，之后可以随时用「打开文件夹」换根，也可以同时开多个窗口。

| 操作 | 结果 |
| --- | --- |
| 单击文件 | 在唯一的预览标签里打开（标签名斜体）；下一次单击会替换它 |
| 双击文件 / 双击标签 | 锁定成固定标签，之后单击别的文件不会顶掉它 |
| 改一个字 | 标签自动锁定，未保存只显示一个金色圆点 |
| 悬停标签 | 圆点换成关闭键；点 `×` 关闭（未保存会先确认），中键点标签也关闭 |
| `Ctrl+S` / 状态栏「保存」 | 保存到磁盘，走 sandbox policy 与文件版本校验；成功只在状态栏亮 1.8 秒「已保存」，不长期挂着 |
| `Ctrl+Shift+B` | 收起 / 展开侧栏（也可以在活动栏点当前图标）。宿主已占用 `Ctrl+B`，编辑器让开这一组 |
| `Ctrl+Shift+E` / `Ctrl+Shift+F` / `Ctrl+Shift+G` | 切到资源管理器 / 搜索（并聚焦输入框）/ 源代码管理 |
| `Ctrl+Shift+H` | 切到搜索并展开「替换为」一行；替换框里按 `Enter` 等于「全部替换」 |
| `Ctrl+Shift+O` | 打开文件夹对话框 |
| `Tab` / `Shift+Tab` | 插入两个空格 / 反缩进；选中多行时整块缩进或反缩进 |
| `Enter` | 继承当前行缩进；行尾是 `{ ( [` 或 `:` 时再缩两格 |
| 标题栏右侧 `—` / `□` / `×` | 最小化 / 最大化（已最大化时是还原）/ 关闭 |
| 双击标题栏 | 最大化 / 还原 |

- **活动栏**：左侧 48px 图标列——资源管理器 / 搜索 / 源代码管理，激活项白色并带左侧白条；有 Git 改动时第三个图标右下角挂数字徽标；底部是侧栏折叠键。
- **侧栏**：标题行显示当前视图名与视图动作（刷新目录、全部折叠、清空搜索、展开/折叠全部结果）；右边缘可以拖动改宽（168–460px，双击复位 220px），宽度、折叠状态和当前视图都写进 `localStorage`。
- **树**：折叠箭头在名字左侧、展开旋转 90°；目录就地展开不跳转；长目录只滚动树本身。
- **当前行**：光标所在行有一条很淡的底纹，行号同时变亮；焦点在侧栏时底纹变淡但位置还在。选区、光标、滚动条都按 VSCode 深色配色。
- **状态栏**：左边是工作目录与 `⎇ 分支`（带 ↑↓ 领先落后），右边依次是 `行 L, 列 C`、换行符、编码（BOM 会写成 `UTF-8 BOM`）、语言、行数，最后是保存键——只有打开了文件才出现，没文件时不摆一排空按钮。
- **打开过程**：文件还在读时编辑器里是转圈 + 文件名，不会先闪一下欢迎页再跳成内容。
- **输入不会毁掉撤销**：缩进、自动缩进都走原生 `insertText`，`Ctrl+Z` 能一路退回，不会像直接改 `value` 那样把撤销栈清空。
- **大文件**：行号与高亮都是虚拟化渲染（只画 `视口/20px + 上下各 8 行`），5 万行的文件滚动仍然顺；行数用一遍 `charCodeAt` 数出来，不做 `split`；行号槽宽度随位数变化，6 位行号也不会被裁。
- **不骗人**：没有终端、扩展市场、调试器，界面上也只有真正能用的三栏——资源管理器、搜索、源代码管理。

## 手机上的样子

窗口在 `≤600px` 视口下铺满整屏，于是三件事必须重排：

- **侧栏是抽屉**：默认收起，点活动栏图标才拉出来；展开时宽 `272px`（右边一定留一条看得见、点得到的正文），压一层 `rgba(0,0,0,.5)` 遮罩，遮罩从活动栏右边开始。点文件、点遮罩都会收起。这个展开状态只活在当前窗口，不写进 `dsh.world.vscode.sidebar`。
- **标题栏只有 `×`**：最小化 / 最大化在满屏窗口上没有落点，双击标题栏也不再触发最大化。
- **正文 `14px / 22px`，默认自动换行**：状态栏右侧的「换行 开 / 关」切换（桌面是 `Alt+Z`）。折行时行号与当前行底纹仍然在——它们按镜像层量出来的「每行真实高度」定位，不再拿行高去乘；语法高亮层依旧让位（逐 token 逐行渲染，折行后没法与 textarea 逐字对齐）。手机上读代码优先看得全，所以默认选折行。

| 手机上专门放大过的尺寸 | 桌面 | 手机 |
| --- | --- | --- |
| 文件树行 | `24px` | `40px` |
| 侧栏标题行 / 动作键 | `30px` / `22×22` | `44px` / `32×32` |
| 搜索框 / 命中行 | `26px` / `22px` | `40px` / `36px` |
| 标签栏 / 标签关闭键 | `36px` / `18px`（hover 才现身） | `40px` / `26px` 常显 |
| 打开文件夹：行 / 路径输入 / 底部按钮 | `26px` / `24px` / `26px` | `40px` / `34px` / `40px` |
| 状态栏 | `24px`，`行 L, 列 C` + `LF` + 编码 + 语言 + 行数 | `28px`，`L:C` + 换行开关（`LF` / 编码 / 语言 / 行数 隐藏） |
| 活动栏（左侧图标列） | `48px` | `40px` |
| 行号槽 | `46px` 起，`13px` 字 | `26px` 起（`12 + 位数 × 6.9`），`11px` 字 |

「打开文件夹」在手机上铺满整屏，说明文字独占一行、三个按钮一行平分——否则那句说明会被挤成竖排。软键盘弹起时按 `visualViewport` 的高度差把窗口收上去，正在编辑的行不会被键盘压住。

## 打开文件夹

标题栏的文件夹图标、资源管理器标题行的第一个按钮、状态栏左侧的 `◆ 文件夹名`、欢迎页的按钮，四个入口都能打开同一个对话框；`Ctrl+Shift+O` 也行。

| 元素 | 行为 |
| --- | --- |
| 路径框 | 可直接输入或粘贴路径，`Enter` 跳转；每次进入子目录、回上一级都会同步成当前路径 |
| 最近打开 | 对话框顶部列出最近 8 个打开过的文件夹（去重、最新在上、当前根不重复列出），点一条直接切根；最多露约五行，其余在栏内滚动 |
| 上一级 | 走到盘根（或文件系统根）时置灰 |
| 目录列表 | 只列文件夹，按名字排序；空目录给一句「这个文件夹里没有子文件夹」 |
| 打开 | 当前窗口换根：关掉现有标签（有未保存会先确认），资源管理器、搜索、Git 全部跟着换 |
| 在新窗口打开 | 新开一个窗口打开这个文件夹，当前窗口一点不动 |
| 键盘 | 对话框是模态的：`Esc` 关闭（焦点在输入框、列表行上都算）、`Tab` 在卡片内循环、点卡片外的空白处也能关；此时编辑器快捷键不生效 |

- **根决定一切**：`root` 参数跟着 `open` / `save` / `list` / `search` / `git` 一起发给宿主，所以侧栏、搜索、Git 看的是同一个文件夹，不会一个窗口里两套路径。
- **默认回到上次的文件夹**：桌面图标 / 开始菜单直接打开 VSCode（没有指定文件夹）时，先取「最近打开」列表的第一条；没有历史才退回会话 cwd。显式路径（文件所在目录、打开文件夹对话框、在新窗口打开）始终优先。
- **宿主校验**：文件必须落在当前根里（`open` / `save` 都查），根必须是真实目录；保存仍然走 sandbox policy —— 只读模式下打不开也写不了，工作区外可读但写入会被 `workspace-write` 拦住。
- **工作区外的文件夹也能开**：这是「打开文件夹」的本来意思；能不能写由 policy 决定，不是由窗口决定。

## 对话

标题栏的对话气泡打开一个全宽「对话」编辑器标签，里面是 DSH 原生对话（历史、流式、工具、输入、审批）。标签顶栏从左边起是「会话名 + 当前文件夹 + 下拉」，右侧是「新建会话」。

| 元素 | 行为 |
| --- | --- |
| 目录绑定 | 只列出、只新建 `cwd` 等于 VSCode 当前根目录的会话（Windows 下不区分大小写）；换文件夹时对话标签和其它标签一起关掉，重新打开按新文件夹重新选 |
| 历史会话 | 点顶栏的会话名打开列表（标题 + `运行中` / 最近时间），点一条切过去；子代理会话不列 |
| 新建会话 | 先让宿主把当前根解析成 DSH workspace（已存在复用，不存在登记），再用 `workspaceId` 建会话；建完立即切过去。旧宿主没有解析接口时退回 `cwd`；目录不是真实路径（如 IMA 虚拟根）时把错误原样显示在空态里 |
| 模型切换 | 原生模型菜单关闭后 200ms / 800ms 各刷新一次该会话 projection，触发器的模型名跟上宿主写入的 `modelSelection` |
| 记忆 | 每个文件夹上次选中的会话记在窗口内存里，关掉对话标签再打开会回到那一条；窗口关闭后重置 |
| 输入区 | 打开期间占用 DSH 唯一的原生对话座位，主窗口同一会话的输入区暂时让位；切走或关闭立即恢复。只有焦点所在的 VSCode 窗口挂载对话，多开不会出现两个输入框 |
| 手机 | 顶栏、会话列表、空态按钮都按 36~40px 的触控高度排版 |

## 多开

- **每次打开都是新窗口**：桌面图标、开始菜单「打开」、右键菜单「打开」都新建一个窗口；任务栏每个窗口一项，标签是文件夹名，同名时按「同名里的第几个」加 `(1)` / `(2)`（开一屋子 `src` 不会把另一个 `workspace` 也叫成 `(3)`）。
- **互不干扰**：每个窗口有自己的文件夹、标签、侧栏视图 / 宽度、搜索条件、Git 面板、未保存状态和位置；关掉一个不影响另一个。快捷键也各归各的：按键只发给焦点所在的窗口，点窗口任意位置（含标题栏）都会把焦点接过来，不会出现两个窗口一起保存、一起收侧栏。
- **叠放**：新窗口从默认位置横向错开 60px（正好露出后面窗口的整条活动栏），每满 3 列再往下 26px，第 4 个窗口不会又叠回第一个身上；拖过之后位置会被记住，下次开新窗口还有次序。
- **层级**：所有窗口（含 DSH 主窗口）共用一条激活栈，点哪个哪个到最前；关掉或最小化后由栈里剩下的最上面那个接替。每个窗口标题栏还有一枚图钉，钉住后始终压在未钉住窗口之上。
- **窗口键**：标题栏右侧 `—` `□` `×` 分别是最小化、最大化 / 还原、关闭，只有关闭键 hover 是红的。最大化铺满桌面（桌面顶栏到任务栏之间）并去掉圆角和缩放手柄；双击标题栏也能切换。
- **最小化 / 还原**：最小化时窗口淡出并轻微下沉，任务栏那一格变淡、底下留一条短灰线（表示还在运行），点它还原并**把键盘交回编辑器**——不用再点一下窗口才能按 `Ctrl+S`。最小化前是最大化，还原回来还是最大化；最小化时「打开文件夹」会自动收起，看不见的窗口也不再响应编辑器快捷键。
- **谁在前台**：非活动窗口的标题文字变灰，多开时一眼看出当前操作的是哪个；关掉前台窗口时，前台交给还开着的那一个，而不是直接退回桌面。
- **卸载**：应用卸载会关闭所有 VSCode 窗口，有未保存修改时先确认。

## 语法高亮

编辑器是「透明文字的原生 textarea + 下层高亮层」：输入、光标、选区、滚动、`Ctrl+A` 全还是浏览器原生行为，只是文字颜色由下面那层 token 决定，两层用同一个 `transform: translate(-scrollLeft, -scrollTop)` 跟着滚动，字体、`tab-size`、行高都继承同一套。

- **支持**：JavaScript / TypeScript / JSX / TSX、JSON（区分键与值）、CSS/SCSS/Less、HTML/XML/Vue、Markdown（围栏、标题、列表、行内强调）、Python（含跨行三引号）、Shell、Batch、PowerShell、YAML、TOML、INI、C/C++/Java/C#/Go/Rust 等 C 系、Ruby、Lua、SQL。
- **配色**：VSCode Dark+ 的一套 token 色（注释绿、字符串橙、关键字蓝、控制流紫、函数黄、类型青、数字浅绿、常量浅蓝）。
- **无损**：tokenizer 只切分不重写，任何一行拼回去与原文件逐字节相同（有单测盯着）。
- **长源码**：使用虚拟编辑器按视口着色；不再因为字符数关闭高亮。

## 项目搜索

活动栏第二个图标。输入即搜（停顿 260ms），`Enter` 立刻搜、`Esc` 清空；输入框右侧两个开关是「区分大小写」和「正则表达式」。

| 操作 | 结果 |
| --- | --- |
| 结果行 | `文件 + 目录 + 命中数`，单击展开 / 收起该文件的命中行 |
| 命中行 | 左侧行号、右侧原始代码（超长行以首个命中为中心裁到 400 字符），命中处橙色 `<mark>` |
| 单击命中 | 打开该文件（已打开则直接切过去），光标落到那一行并居中滚动 |
| 汇总行 | `N 个结果 · M 个文件`，被限流时补一句「结果过多，已截断」 |

- **走 `ctx.fs`**：宿主侧 `world/vscode-search.js` 用 `listDir` / `readBytes` 遍历窗口当前打开的文件夹，不依赖 `rg`（用户机器上不一定有），也不碰写权限。
- **跳过噪音**：`node_modules`、`.git`、`dist`、`build`、`out`、`coverage`、`.venv`、`target` 等构建/依赖目录，图片字体压缩包等二进制扩展名，含 `NUL` 的文件，以及单文件 1.2MB 以上的文件。
- **有上限**：200 个文件 / 1000 个结果 / 单文件 50 行 / 20000 个文件 / 12 秒，任一触顶就返回 `truncated`，不会把窗口搜到假死。
- **过滤**：宿主接口支持 `include` / `exclude`（`*.js`、`src/**`、`*.{ts,tsx}`，逗号分隔），界面上暂时没放这两个输入框。

### 替换

侧栏搜索支持**替换**：搜索框左侧的箭头展开「替换为」一行，可以按文件替换，也可以全部替换（先确认）。替换只改当前结果列表点名的文件，不重新扫全盘；打开着且有未保存修改的文件会跳过，避免下一次保存把替换盖回去。正则模式下替换内容支持 `$1` 捕获组，普通模式按字面量写入；原文件的 CRLF / BOM 保持不变。

## 源代码管理（Git）

活动栏第三个图标（带更改数徽标，状态栏的 `⎇ 分支` 点一下也能直接切过去）。支持整文件与逐块暂存/取消暂存、确认后放弃工作区更改、提交、拉取/推送，以及工作区、暂存区和历史提交的只读 Diff。

| 操作 | 结果 |
| --- | --- |
| 分支行 | 当前分支、`↑领先 ↓落后`、刷新按钮；`⎇` 后面就是分支名 |
| 提交信息框 | `Ctrl+Enter` 直接提交；空信息或没有已暂存文件时提交键是灰的 |
| 「提交」 | 提交**全部已暂存**的改动，成功后清空信息框并回显 `[main 1a2b3c4] 标题` |
| 「拉取」 / 「推送」 | `git pull --no-edit`（`pull.rebase=false`，不弹编辑器）/ `git push`，没有上游时用 `push -u origin HEAD` |
| 目录树 | 两组都按仓库相对路径折成目录树，默认全部展开；点目录行收起 / 展开，目录排在文件前、各自按名字排序 |
| 文件行 | 树里缩进显示；单击打开只读 Diff，双击打开源码（并展开所在目录）；悬停出现 `+` 暂存 / `−` 取消暂存 |
| Diff 标签 | 单栏统一 diff：新旧双行号 + `+`/`-` 红绿行、`@@` 段头；正文不再重复 `diff --git` / `index` / `---` / `+++` 四行文件头；已暂存组看索引、更改组看工作区、未跟踪按整份新增 |
| 更改块 | 文本修改的段头提供暂存/取消暂存；上一块/下一块或 F7/Shift+F7 跳转。新增、删除、重命名、模式变化及非 UTF-8 内容用整文件操作 |
| 放弃更改 | 文件右键或工作区 Diff 工具栏，确认后只放弃未暂存修改；保留暂存区，未跟踪文件明确提示删除，有未保存草稿时阻止操作 |
| 最近提交 | 展开 commit 按需读取其改动文件，点击文件打开该版本 Diff；删除和重命名可查看，合并提交按第一父提交比较 |
| 目录行 | 右侧 `+` / `−` 常显（`0.55` 透明度，悬停变实）：一次暂存 / 取消暂存该目录下的全部更改；手机没有 hover 也点得到 |
| 组头 | 「已暂存」「更改」两组，点「多选」可跨目录勾选指定文件，悬停组头的 `+` / `−` 仍操作整组 |
| 状态字母 | `M` 改、`A` 新增、`D` 删除、`U` 未跟踪、`!` 冲突 |

- **状态来源**：`git status --porcelain=v1 -z --branch --untracked-files=all`，一次拿到分支、上游、领先/落后与全部条目；路径用 `rev-parse --show-prefix` 换算成工作区相对路径，所以 `cwd` 是仓库子目录时也能正确打开文件（也兼容 8.3 短路径）。
- **安全**：写操作要过当前 `sandboxPolicy`（`read-only` 直接拒绝，`workspace-write` 要求仓库根在可写根内）；路径参数拒绝绝对路径、`..` 和 `:(magic)`；命令用 argv 数组直传，不经过 shell。
- **不卡窗口**：`GIT_TERMINAL_PROMPT=0`、`GCM_INTERACTIVE=never`，凭据弹窗不会让窗口假死；每条命令带超时（status 20s / commit 60s / pull 180s / push 300s），失败时把 git 的 `fatal:` / `error:` 那行原样回显。
- **范围**：提供上述 Diff、暂存和提交流程；尚未提供分支切换、stash、rebase、冲突解决面板或 `git init`（工作目录不是仓库时只说明情况）。

## Git 文件夹绑定

当前文件夹没有 Git 仓库时，可在「源代码管理 → 选择 Git 文件夹」绑定已有仓库。绑定按当前文件夹记忆，可解除；不会切换工程、复制文件或自动拉取、推送。

## ZIP 工作区与多文件夹

内置 VSCode 的工作区搜索在关键词变化时立即清除旧结果和计数。清空输入框或按 Esc 后，迟到的旧请求也不会把结果再次显示出来。

**VSCode 多文件夹资源管理器**：点击资源管理器标题右侧的 **＋（添加文件夹到工作区）**，选好目录后点 **添加**。目录并列显示，原有标签和未保存的编辑不会关闭；刷新桌面时会恢复该窗口的目录列表。搜索和 Git 仍沿用原目录或已有的 Git 绑定。

打开工程时，桌面快捷方式和 VSCode 文件树会合并同一会话、同一路径的进行中请求，并提示正在打开的文件名。ZIP 缓存只留目录信息，按最近使用顺序和总节点数淘汰。可用 `npm run test:zip-index` 复测内存和冷、热打开耗时；ZIP 写回和 PB 工程解析规则不变。

内置 VSCode 可把 ZIP 当作工作目录：在文件树里点 ZIP，或把 `.zip`、`.pbt`、`.exe` 拖到 World 桌面，双击快捷方式直接进入对应工程（不会运行 EXE）。ZIP 按需读取文件；Ctrl+S 把可编辑的 UTF-8 文本写回原 ZIP，不生成解压目录。未修改条目保留压缩数据；只读权限、外部修改冲突和加密条目不会被强行覆盖。

## PB 对象查找

内置 VSCode 的 Script 右键查找读取当前 EXE/PBD 的真实二进制对象名：`w_cdwh` 会列出同名对象，`w_cdwh.win` 或 `w_cdwh.srw` 只打开对应的窗口源码。首次查询批量建立索引，后续右键复用；刷新资源管理器可重读。

## PB 工程：分类、运行与打包

打开已登记的 PBT 或 PowerBuilder EXE 后，展开 PBL 或 PBD 可按 PB 对象类型浏览。每个库的「最近修改」按对象自身的修改时间倒序列出最多 10 个对象，不再分类型；这些都是原对象的入口。普通文件夹不分组。活动栏「运行」（手机在「视图」菜单中）仅打开面板。按钮「运行项目」与当前编辑器窗口的 F5 相同：PBT 使用已保存的库，不查找或构建同名 EXE；EXE 工程则启动自身。未保存的草稿需先确认，不会被写入或丢弃。

**PB8 PBT** 使用 PB8 IDE 的原生「运行 (Ctrl+R)」：宿主在临时目录创建一个只包含所选 PBT 的工作区，启动独立的 `pb80.exe`，只向该进程已就绪的工程窗口派发运行命令，不操作系统键盘、不使用旧 EXE。默认从 Windows App Paths 查找 PB8，免安装版可设置 `WORLD_PB80_IDE` 为 `pb80.exe` 的绝对路径。不会自动提升权限、确认业务提示或修改工程 DLL。原生「运行」时，应用从 **PBT 所在目录**读取相对路径（如配置文件）。如果应用 PBL（`applib`）不在该目录，启动器会在那里创建仅用于本次运行的临时 PBT 和应用库副本，保留其他库的路径与顺序，IDE 退出后清理；不会覆盖原 PBT 或 PBL。分目录工程需要 PBT 目录可写，否则报错，不会改从其他目录启动。两者同目录时直接运行原工程。PB9+ PBT 和直接打开的 EXE 不走此兼容路径。

宿主从相邻的 `pbnpm-pbd` 插件取得 x86 pypower 运行时，PBVM 版本来自登记的当前工程。打包 PBT 时指定**尚不存在的输出目录**，可选嵌入库或生成外置 PBD、图标和 PBR。ORCA 在库副本上重建，成功后才发布整个目录；已有 PBD 依赖作为外置文件交付。输出不包含 PBVM 或其他第三方运行库。仅有二进制应用时，需先还原为 PBT/PBL 再打包。

针对性验证：`node tests/pb-project-browser.mjs`（无头浏览器），`node --test tests/pb-actions.test.js tests/workspace-roots.test.js`，以及 Windows 上的 `node tests/pb-project-native.mjs`（临时 PB9 工程，检查首个测试窗口是否可见）。设置 `WORLD_PB_TEST_VERSION=80` 后，同一测试通过原生 PB8 IDE 分别核对 PBT 与应用 PBL 同目录、不同目录时 `GetCurrentDirectory()` 的实际返回值。

## 运行批处理

- **运行批处理**：在文件树右键 `.bat` / `.cmd` 选「运行批处理」；打开批处理文件后标题栏也会出现运行键。输出面板流式显示命令输出，结束后报退出码，可随时停止或关闭。
- **`Ctrl+B` 不再和宿主抢**：编辑器侧栏改用 `Ctrl+Shift+B`。宿主默认把 `Ctrl+B` 留给 DSH 左侧栏，两边不再同按一次。
- **快捷键整体截断**：`Ctrl+S`、`Ctrl+Shift+E/F/G/H/O`、`Alt+Z` 和 `Ctrl+Shift+B` 都改在 window 捕获阶段消费，宿主收不到同一次按键，只有当前 VSCode 窗口响应。
- **自检**：`node tests/browser.mjs` 覆盖批处理右键运行、输出面板、退出码，以及 `Ctrl+Shift+B` 只折叠当前窗口侧栏。

- **占满正文**：运行批处理时输出区直接占满标签栏以下的整块编辑器空间，不再只占底部一小条；关闭输出后回到原来的标签。
- **细节**：头部显示运行中 / 已停止 / 退出码和耗时；输出区加大内边距、`tab-size: 4` 与 1.6 行高，长行自动换行。
- **自检**：`node tests/browser.mjs` 断言输出高度等于编辑器正文减去标签栏，并跑通运行、输出、退出码与关闭。

- **收起后台跑**：输出头新增「收起」——进程不中断，编辑器立刻回到批处理文件内容；状态栏出现「● 输出」，点一下重新展开运行面板。
- **三种退出方式**：收起只挡界面，停止结束进程，关闭会先确认再停止并清掉面板；结束后「收起」仍可用，状态栏入口变成「输出」。
- **自检**：`node tests/browser.mjs` 覆盖运行 → 收起 → 批处理文件可见 → 状态栏回收入口 → 退出码 0，并恢复 `main.js` 供后续高亮断言。

## Markdown 文件内的 PBTest

Markdown 标题旁的箭头可折叠整个章节，包含下级标题，不影响下一个同级或更高层级的章节。重新展开后，内部 `pbtest` 代码块原有的折叠状态会保留。

在 World 的内置 VSCode 打开 `.md` 或 `.markdown` 时，`pbtest`、`powerscript` 和 `powerbuilder` 围栏会按 PowerScript 高亮；示例中的 `@c … @end c` 按 C/C++ 高亮。点标题栏 **文件内单元测试** 打开用例列表，可运行整篇文档、一个围栏或一个 `test_` 函数/子程序。普通单栏编辑器也可点围栏或用例行号处的 **▶**。结果和错误显示在输出面板，可停止、收起或关闭。

运行需要 Windows、可用的 `pbnpm.exe`（优先使用相邻的 pbnpm 插件，再查 PATH）及用例所需的 PB 运行库。请先保存 UTF-8 文档；只读会话不能执行。传给 CLI 的是原 Markdown 文件，不复制代码块，因此文档头部的 PB 版本、DLL 目录和相对引用仍有效。只运行你信任的测试文档。

## 大文件的两种视图

沿用原有大小限制：文件仍由宿主读取（上限 16 MiB）。已载入的文本按大小分三档：

- **不超过 1 MiB**：普通 textarea 编辑器，带语法高亮和折行。
- **1–8 MiB**：随插件打包的 CodeMirror 视图，只渲染视口附近的行，**可编辑**。滚动、全文查找替换、选择、复制、自动换行、分栏、撤销重做都走完整文件；打字不触发 React 重渲染，保存时才一次性取全文做版本校验。
- **超过 8 MiB**：同一个视图，但只读浏览——保存要一次性把全文取出来，再大那一下会有明显停顿。

后台的大文件标签保留原文、选区和阅读位置，不保留排版视图；切回来不重新读盘。可编辑标签在切到后台前会把全文写回快照，所以未保存的改动不会丢。

开发复测：在本机 DSH 测试环境运行 `node tests/million-lines-browser.mjs`，会生成临时 200 万行文本和一个 1.2 MiB 的可编辑文件，通过真实文件服务打开，检查文末、行号、查找、跨屏复制，以及「编辑 → 存盘 → 切标签回来改动还在」。

加 `--memory` 可复测重复打开、切到后台、关闭标签和关闭窗口后的内存回收。后台的大文件标签保留原文、选区和阅读位置，不保留排版视图；切回来不重新读盘。测试报告中的 GC 只用于测量，不会在实际使用时强制触发。

## 与 IMA、PowerBuilder 插件协作

桌面上装了 `ima`、`pbnpm`、`pbnpm-pbd` 时，VSCode 窗口和终端会顺带把它们的入口接出来——不是重写一套文件树，而是把「已经挂好的虚拟目录」和「已经登记的工程」交给同一个编辑器。

- **侧栏的「插件位置」**：资源管理器底部列出 IMA 与每一个已登记的 PowerBuilder 工程（`.pbt` / `.exe`，带 PB 版本与库数量）。点一行就换根：树、搜索、Git 都跟着换；当前所在的那一行高亮。IMA 没授权时那一行是灰的，标题里说明原因，不会假装点得动。
- **「打开文件夹」里也有同一份快捷入口**：对话框顶部列出同样的条目，点一下直接打开，不用从盘符一层层点进去。
- **树里的 `.pbt` / `.exe` 是工程入口**：单击不是「用文本编辑器打开」，而是交给 `pbnpm-pbd-project/open`（PBT 再退回 `pbnpm-project/open`）解析依赖，然后跟到它生成的 `<名字>.workspace` 目录——里面是虚拟的 PBL/PBD 对象，点开就是源码。不是 PowerBuilder 的 exe 会明确报错，不会静默当成二进制文件。
- **别把虚拟目录当普通文件夹**：IMA 的文档和 PBL 对象都不在磁盘上，shell、`rg`、系统资源管理器进不去；编辑器与搜索走宿主 fs，能看到也能改（保存由各自插件负责：IMA 生成新版本，PBL 编译写回）。
- **`pbnpm` 直接进 PATH**：终端启动每条命令时把插件自带的 `bin/` 目录放到 PATH 最前面，`cmd` 里敲 `pbnpm list` / `pbnpm check` 就能用。pbnpm 的中文输出是 GBK（`chcp 65001` 也改不了），所以 PATH 最前面还放了一个同名 `pbnpm.cmd` 包装，用宿主自己的 node 按 GBK 增量解码再以 UTF-8 输出——不转码的话终端里满屏乱码。`help` 里会多一行 `pbnpm <命令>`，说明它已经在 PATH 里。
- **探测只读**：`world-vscode-roots/scan` 只读文件系统（`$DSH_HOME/ima/knowledge.workspace`、`$DSH_HOME/pbnpm(-pbd)/projects.json`），过滤掉目录已经不存在的工程、按 root 去重，不替别的插件做授权，也不改它们的登记文件。
- **自检**：`tests/workspace-roots.test.js` 6 项（两种安装布局的 bin 探测、IMA 挂载与未授权、双登记去重与失效过滤、坏 JSON）；`tests/terminal.test.js` 12 → 14 项（PATH 前缀与包装脚本、没有 pbnpm 时不动 PATH）；浏览器组 `roots-browser` 走真窗口：插件位置三条、`.exe` 在树里是工程入口、点 IMA 换根、对话框里的快捷入口、点 `tj.exe` 调到 `pbnpm-pbd-project/open` 并跟到 workspace。
